# คู่มือตั้งค่าซิงก์เรียลไทม์ (Firebase แผนฟรี)

> **สถานะ: ตั้งค่าเรียบร้อยแล้ว (18 พ.ย. 2569)** — โปรเจกต์ Firebase `character-bingo` (แผน Spark ฟรี, ฐานข้อมูลที่สิงคโปร์)
> ทดสอบบนเว็บจริงผ่านแล้ว อาจารย์ไม่ต้องทำขั้นตอนด้านล่างอีก เก็บไว้เป็นข้อมูลอ้างอิงเผื่อต้องตั้งค่าใหม่

ระบบซิงก์มี 2 แบบ ใช้ร่วมกันได้

| แบบ | ต้องตั้งค่าไหม | ทำอะไรได้ |
|---|---|---|
| **QR ซิงก์** | ไม่ต้อง ใช้ได้ทันที | ผู้เล่นกด “📷 ซิงก์จากจอ” แล้วสแกน QR ซิงก์บนจอพิธีกร มือถือจะรู้ว่าตัวไหนถูกเรียกแล้ว |
| **ซิงก์เรียลไทม์** | ต้องตั้งค่า Firebase ครั้งเดียว (ประมาณ 10 นาที) | มือถืออัปเดตเองทันทีที่พิธีกรสุ่ม **และไม่ให้แตะตัวที่ยังไม่ถูกเรียก** |

ถ้าระบบซิงก์ล่ม เกมจะกลับไปทำงานแบบเดิมเอง คือผู้เล่นแตะเอง แล้วตรวจรางวัลจากหน้าพิธีกร

## สิ่งที่มือถือผู้เล่นทำได้เมื่อซิงก์อยู่

- แสดงแถบ “รอบที่ … · เรียกแล้ว … ตัว · ล่าสุด …” พร้อมภาพตัวล่าสุด
- ช่องที่ถูกเรียกแล้วมีป้ายสีเขียว **เรียกแล้ว**
- **ซิงก์เรียลไทม์ (จุดสีเขียว):** แตะตัวที่ยังไม่ถูกเรียกไม่ได้ ระบบจะเตือน “ยังไม่ถูกเรียก”
- **ข้อมูลไม่สด** (เน็ตหลุด หรือซิงก์ผ่าน QR, จุดสีส้ม): แตะได้ แต่ช่องที่ยังไม่ยืนยันจะขึ้น **กรอบเส้นประสีส้ม** และจะไม่ขึ้น BINGO จนกว่าจะยืนยัน
- เมื่อพิธีกรเริ่มรอบใหม่ มือถือจะแจ้งให้เลือก “ล้างเครื่องหมาย” หรือ “ขอบัตรใบใหม่”
- พิธีกรสุ่มแล้ว มือถือจะเห็นตัวใหม่**หลังจากภาพบนจอเปิดเผยแล้ว** ไม่เห็นก่อนจอใหญ่

## แผนฟรี (Spark) พอไหม

- Firestore แผนฟรีอ่านได้ 50,000 ครั้งต่อวัน และเขียนได้ 20,000 ครั้งต่อวัน **รีเซ็ตทุกวัน**
- เล่นกับผู้เล่น 100 คน 1 รอบเต็ม (24 ตัว) ใช้การอ่านประมาณ 2,500 ครั้ง จึงเล่นได้ประมาณ **20 รอบต่อวัน**
- แผนฟรี**ไม่ต้องใส่บัตรเครดิต และไม่เก็บเงินอัตโนมัติ** ถ้าโควตาเต็ม ระบบซิงก์จะหยุดจนกว่าจะรีเซ็ต แต่เกมยังเล่นต่อได้
- **ถ้า Firebase ชวนให้อัปเกรดเป็นแผน Blaze ให้กดข้าม** ไม่จำเป็นต้องใช้

## ขั้นตอนตั้งค่า (ทำบนคอมพิวเตอร์ ประมาณ 10 นาที)

### 1. สร้างโปรเจกต์

1. เปิด <https://console.firebase.google.com> แล้วล็อกอินด้วยบัญชี Google
2. กด **Create a project** (หรือ **Add project**) ตั้งชื่อ `character-bingo`
3. หน้าถามเรื่อง Google Analytics ให้**ปิด** แล้วกด **Create project**

### 2. สร้างฐานข้อมูล Firestore

1. เมนูซ้าย **Build › Firestore Database** → **Create database**
2. Location เลือก **asia-southeast1 (Singapore)** (เปลี่ยนภายหลังไม่ได้)
3. เลือก **Start in production mode** → **Create**
4. ไปที่แท็บ **Rules** ลบข้อความเดิมทั้งหมด แล้ววางข้อความจากไฟล์ `firebase/firestore.rules` ใน GitHub → กด **Publish**

### 3. เปิดการล็อกอินแบบไม่ระบุตัวตน (สำหรับเครื่องพิธีกร)

1. เมนูซ้าย **Build › Authentication** → **Get started**
2. แท็บ **Sign-in method** → เลือก **Anonymous** → เปิด **Enable** → **Save**
3. แท็บ **Settings › Authorized domains** → **Add domain** → ใส่ `kunnaifoodanube.github.io`

### 4. ดึงค่าตั้งค่ามาใส่ในเว็บ

1. กดรูปเฟือง ⚙️ ข้าง Project Overview → **Project settings**
2. เลื่อนลงไปที่ **Your apps** → กดไอคอนเว็บ **`</>`** → ตั้งชื่อ `bingo-web` → **Register app** (ไม่ต้องติ๊ก Hosting)
3. จะมีโค้ดที่หน้าตาประมาณนี้

   ```js
   const firebaseConfig = {
     apiKey: "AIza....",
     authDomain: "character-bingo-xxxx.firebaseapp.com",
     projectId: "character-bingo-xxxx",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "1:...:web:..."
   };
   ```

4. **ส่งค่าทั้งก้อนนี้ให้ Claude ในแชท** แล้ว Claude จะใส่ให้และอัปโหลดขึ้น GitHub
   ถ้าจะใส่เอง ให้เปิดไฟล์ `firebase-config.js` บน GitHub → กดรูปดินสอ → แทน `null` ด้วยค่าข้างบน (เฉพาะส่วนที่อยู่ใน `{ … }`) → **Commit changes**

> ค่าเหล่านี้**ไม่ใช่รหัสผ่าน** เว็บทุกเว็บที่ใช้ Firebase เปิดเผยค่านี้อยู่แล้ว ความปลอดภัยมาจาก Rules ในขั้นที่ 2
> ซึ่งอนุญาตให้ทุกคน “อ่าน” ได้อย่างเดียว ส่วนการ “แก้” ทำได้เฉพาะเครื่องพิธีกรที่สร้างห้องเท่านั้น

## ตรวจว่าใช้งานได้

1. เปิดหน้าพิธีกร ป้ายด้านบนต้องขึ้น **ซิงก์: ส่งแล้ว ✓**
2. กด **QR เข้าเกม** ลิงก์ใต้ QR ต้องลงท้ายด้วย `&room=…`
3. สแกนด้วยมือถือ → รับบัตร → ต้องเห็นแถบ “รอบที่ 1 · เรียกแล้ว 0 ตัว” และมีจุดสีเขียว
4. ลองแตะช่องใดก็ได้ → ต้องขึ้นว่า “ยังไม่ถูกเรียก”
5. พิธีกรกดสุ่ม → ภายใน 1–2 วินาทีหลังจอใหญ่เปิดภาพ มือถือต้องขึ้นป้าย “เรียกแล้ว”

## ข้อควรรู้

- **ใช้เครื่องและเบราว์เซอร์เดิมเป็นเครื่องพิธีกรตลอดงาน** ห้องซิงก์ผูกกับเครื่องที่สร้าง
  ถ้าเปลี่ยนเครื่องกลางงาน หน้าพิธีกรจะสร้างห้องใหม่ให้เอง แต่ผู้เล่นต้อง**สแกน QR เข้าเกมใหม่**เพื่อเปิดซิงก์ (บัตรเดิมยังใช้ได้)
- นักเรียนที่เปิดหน้า `host.html` เอง จะแก้ข้อมูลห้องของพิธีกรตัวจริงไม่ได้ เพราะ Rules ไม่อนุญาต
- เครือข่ายบางแห่งบล็อกการเชื่อมต่อแบบเรียลไทม์ ถ้าแถบซิงก์ไม่ขึ้นจุดเขียว ให้ใช้ **QR ซิงก์**แทน หรือเล่นแบบแตะเอง

## อัปเดต พ.ย. 2569: จับเวลาแตะ + สิทธิ์สลับบัตร

- **จับเวลาแตะ** (ใช้ได้ทันที ไม่ต้องตั้งค่าเพิ่ม): จอพิธีกร › ช่อง “เวลาให้ผู้เล่นแตะคำ (ต่อภาพ)” ค่าเริ่มต้น 5 วินาที เลือก 3–20 วินาที หรือไม่จับเวลา
  ภาพขึ้นจอแล้วผู้เล่นมีเวลาตามที่ตั้ง แตะได้เฉพาะคำที่ถูกเรียก หมดเวลาแล้วคำนั้น “พลาด” แตะไม่ได้อีก ช่องที่แตะแล้วยกเลิกไม่ได้
  ระหว่างจับเวลา มือถือไม่บอกว่าช่องไหนถูกเรียก (ต้องหาเอง) · ใช้ได้เฉพาะมือถือที่เชื่อมจอพิธีกรแบบเรียลไทม์ (บัตรกระดาษ / QR ซิงก์ ไม่จับเวลา)
- **สิทธิ์สลับบัตร** (ต้องอัปเดตกฎ Firestore 1 ครั้ง): Firebase Console › โปรเจกต์ › Firestore Database › แท็บ Rules › ลบของเดิม วางเนื้อหาไฟล์ `firebase/firestore.rules` ทั้งหมด › Publish
  ~~ติ๊ก “เปิดสิทธิ์สลับบัตร”~~ → เปลี่ยนเป็น **ช่วงสลับบัตร** แล้ว (ดูหัวข้อถัดไป)
  ตอนตรวจบัตร จอพิธีกรใช้ตำแหน่งจริงบนเครื่องผู้เล่น และถ้าจับเวลาอยู่ จะนับเฉพาะคำที่ผู้เล่นแตะทันเวลา
- ยังอยู่ในแผนฟรี (Spark): มือถือเขียนข้อมูลเฉพาะเมื่อแตะหรือถูกสลับ รายชื่อเพื่อนโหลดเฉพาะตอนเปิดหน้าต่างเลือก

## อัปเดต 19 พ.ย. 2569 (v1.5.7 / Galactic v1.6.1): ช่วงสลับบัตร — พิธีกรกดเปิดเมื่อต้องการ

- ใต้จอใหญ่มีปุ่ม **🔀 เปิดสลับบัตร 10 วิ** (เลือกระยะเวลา 5/10/15/20/30 วินาทีที่แผงขวา “ช่วงสลับบัตร”)
- กดแล้ว จอโปรเจกเตอร์ขึ้นป้ายนับถอยหลัง “สลับบัตรได้แล้ว!” · มือถือสั่น + ขึ้นปุ่มสลับบัตรพร้อมเวลาที่เหลือ
- ระหว่างช่วงนี้ ผู้เล่นแตะชื่อเพื่อน (หรือ “บัตรของฉันเอง”) แล้ว**สลับทันที** — สิทธิ์ 1 ครั้งต่อรอบ
- ไม่ใช้ = **เก็บสิทธิ์ไว้** ใช้ในช่วงสลับครั้งถัดไปของรอบเดียวกันได้ (เช่น รอให้โดนเพื่อนสลับก่อน แล้วค่อยสลับบัตรตัวเองคืน)
- ครบเวลาแล้วปิดเอง หรือกดปุ่มเดิมอีกครั้งเพื่อปิดก่อนเวลา · เปิดกี่ครั้งก็ได้ต่อรอบ
- ถ้าจอพิธีกรขึ้นข้อความ “⚠️ ระบบสลับบัตรยังไม่พร้อม” แปลว่ายังไม่ได้อัปเดตกฎ Firestore ตามหัวข้อด้านบน (ทำครั้งเดียว ไม่ต้องทำทุกครั้งที่จัดกิจกรรม)
- **โดนเพื่อนสลับได้ไม่เกิน 2 ครั้งต่อรอบ** (สลับบัตรตัวเองไม่นับ → บัตรเปลี่ยนได้มากสุด 3 ครั้งถ้าเก็บสิทธิ์ไว้ช่วยตัวเอง) · รายชื่อเพื่อนบอก “โดนสลับแล้ว 1/2” และกดคนที่ครบแล้วไม่ได้ · ถ้ากดพร้อมกันแล้วเพื่อนครบโควตาไปก่อน คนกดได้สิทธิ์คืน
- ทดสอบอัตโนมัติ `tests/e2e_timer_shuffle.py` ผ่าน 17/17 ทั้ง Film & Animation และ Galactic (ระบบซิงก์จำลอง)

## อัปเดต 21 พ.ย. 2569 (v1.6.0 / Galactic v1.6.4): แถบสลับบัตรบนบัตร + หน้าต่างเลือกเด้งเอง 30 วิ

- มือถือมีแถบ **🔀 สลับบัตร** เหนือบัตรตลอดเวลา บอก “สิทธิ์ของฉัน 1/1 (หรือ 0/1)” และ “โดนเพื่อนสลับ 0/2 · 1/2 · 2/2”
- พิธีกรกด **🔀 เปิดสลับบัตร** → มือถือทุกเครื่องที่ยังมีสิทธิ์**เด้งหน้าต่างเลือกขึ้นมาเอง** พร้อมนับถอยหลัง (ค่าเริ่มต้น **30 วินาที** · เลือกได้ 10–60 วิ)
- ในหน้าต่าง: ชื่อเพื่อนทุกคนเป็นปุ่มใหญ่ แต่ละชื่อบอก “โดน 0/2 · 1/2 · เต็มแล้ว 2/2” (คนที่เต็มแล้วกดไม่ได้) · **ลำดับชื่อสุ่มแยกแต่ละเครื่อง** ไม่เรียงตามชื่อ คนที่ชื่ออยู่บนสุดจึงไม่โดนบ่อยกว่าคนอื่น · **“บัตรของฉันเอง” อยู่แถวกลาง** แถบสีเหลืองเต็มความกว้าง
- แตะเลือก 1 คน → กด “🔀 สลับบัตรของ …” เพื่อยืนยัน · กด “เก็บสิทธิ์ไว้ก่อน” = ไม่สลับตอนนี้ (แตะแถบบนบัตรเปิดหน้าต่างใหม่ได้จนหมดเวลา)
- ระหว่างเปิดช่วงสลับ จอพิธีกร**สุ่มตัวถัดไปไม่ได้** (กันหน้าต่างบังบัตรตอนจับเวลาแตะ) — รอหมดเวลา หรือกด ⏹ ปิดก่อน
- ไม่ต้องแก้กฎ Firebase เพิ่ม · ทดสอบอัตโนมัติ `tests/e2e_timer_shuffle.py` ผ่าน 20/20 ทั้ง Film & Animation และ Galactic
